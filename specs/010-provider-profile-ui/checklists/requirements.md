# Specification Quality Checklist: Alta y perfil visual de Proveedor

**Purpose**: Verificar que el recorrido visual del proveedor tenga un alcance claro, manual y listo para planificarse.

**Created**: 2026-09-15

**Feature**: [spec.md](../spec.md)

## Content Quality

- [x] No incorpora decisiones técnicas como requisitos de producto.
- [x] Mantiene separado el alta individual de Proveedor del perfil de Cliente.
- [x] Usa lenguaje de producto y diseño comprensible para un oficio no técnico.
- [x] Todas las secciones obligatorias están completas.

## Requirement Completeness

- [x] Incluye una sola categoría inicial, guardado de borrador y revisión previa.
- [x] Define datos progresivos por categoría: tareas, modalidad, cobertura, disponibilidad, experiencia y precio.
- [x] Trata la matrícula como declaración opcional, no como verificación ni ventaja automática.
- [x] Define los seis estados de proveedor y sus acciones permitidas.
- [x] Incluye casos de categoría indisponible, cambio de categoría, conexión, motivos ausentes y estados no reenviables.
- [x] Excluye documentos sensibles, pagos, ranking, empresa y contratación.
- [x] Identifica la dependencia con 003, 005 y el futuro panel 012.

## Frontend Quality Guardrails

- [x] Establece naranja predominante de Proveedor y azul de acento.
- [x] Exige curvatura continua G2 y prohíbe bordes decorativos o marcos repetidos.
- [x] Prioriza títulos breves, una decisión por pantalla y evita texto o tarjetas redundantes.
- [x] Conserva el recorrido manual aunque Jorge pueda ayudar opcionalmente.
- [x] Incluye carga, vacío, error, borrador, soporte, claro/oscuro, texto ampliado, lector de pantalla y movimiento reducido.

## Notes

- Las tareas, modalidades y precios exactos por categoría requieren configuración posterior y revisión regulatoria antes de operar categorías sensibles.
